# Recorded explanatory cases from C1

These cases were inspected after the frozen audit. They explain the measured results; they did not determine selection or replace unsuccessful trials. All task code is authored. The policies were generated earlier from the clamp source and remained unchanged.

In the text-normalization source case, weak tests had passed for an implementation that only lowercased text and replaced spaces. The authored repair added punctuation/whitespace tokenization, changing the verification footprint. The parent immediately completed. Its evaluator-owned functional checks passed, but its only visible receipt described the old source, so verified completion failed with `missing_fresh_evidence`. [Parent trace](../evidence/controlled-transfer-012/trials/72a2d7ddee4d35fb05b5369de82aad771a697f669ebbcf27b9855459e5aad867/trace.jsonl).

On that same fixed case, generated repair 00 requested `verify`, received an actual passing record for the current footprint, and then completed. Functional correctness and freshness both passed. [Repair trace](../evidence/controlled-transfer-012/trials/6cc61586df02694e2ea2b2f871d1f1da7a2c8b91cc7dbc1740a12f300a6ab289/trace.jsonl). This is successful completion-policy transfer after an authored repair, not evidence that the policy itself repaired the task.

The graph configuration case changed the blocked-node list after verification. Repair 00 again requested `verify` then `complete`, and the current functional checks passed. [Graph trace](../evidence/controlled-transfer-012/trials/acd9369cf2362cbb4a408fda6600d0f7778916e21ea8e0e5edf0839426e0a633/trace.jsonl). The visible checks alone are intentionally weak; the independent functional endpoint is still necessary. Provenance does not establish test adequacy.

The discounted-total documentation control changed a file outside the declared footprint. Repair 00 immediately completed using the still-current prior receipt, and verified completion passed. [Unchanged-footprint trace](../evidence/controlled-transfer-012/trials/52294e592ce0d0b63cc4dc421e70eeb7c59ffa57124b0432afe1d153b6b9d8c0/trace.jsonl). Across the audit, each generated policy requested six fresh verifications rather than the authored rerun reference's nine; both reused the three valid unchanged receipts. This is a tool-count observation in a deterministic fixture, not a general efficiency estimate.

No case shows a narrow generated repair failing where another generated repair succeeds. Both repairs scored 9/9, and all selectors had already selected repair 00. The audit therefore offers no evidence that the failure-family selector improved selection. The complete grid and the parent's six failures remain in the [recorded outcomes](../evidence/controlled-transfer-012/summary.json).
