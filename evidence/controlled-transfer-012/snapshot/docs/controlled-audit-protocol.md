# Controlled transfer pilot: amendment C1

2 November 2026, written before executing the new templates. This explicitly narrows the next experiment; it does not complete the originally proposed native-agent main study.

The three-call feasibility budget is exhausted. Both source-conditioned generated policies are uniformly successful on development cases. We will retain this unfavorable feasibility finding and finish a small **controlled transfer pilot** using the same unchanged pool and already recorded selection decisions. We will not search for a favorable pool, manufacture a narrow generated repair, or treat the authored Shinka adapter as a model repair. No additional inference is authorized or needed.

## Frozen inputs and separation

The parent and two model-generated policies come from `evidence/frozen-pool-001/pool.json`. They were generated from an authored clamp failure. The 60 matched development trials have already selected `repair-00` under source-only, generic and failure-family selection. Before audit execution, replay all those traces, recompute the decisions, and bind their plan, summary and pool identities into the new freeze. Candidates and decisions cannot change after seeing audit outcomes.

Audit templates implement three separately authored tasks: text slug normalization, discounted integer-cent totals, and graph reachability with blocked nodes. None is the clamp development template. Every template has three cases: a relevant source repair after a weak visible test passed; a configuration change after passing verification; and an unrelated documentation change. Visible and evaluator-owned functional assertions remain distinct. The functional oracle must actually pass; an old receipt alone never establishes functional correctness. Old evidence and current fingerprints remain observable, preserving the policy interface and information available during development.

There are nine semantic cases, one deterministic execution per candidate/case. The three candidates and one fixed authored rerun reference give **36 audit trials**. The reference is not selectable. All four programs execute only in the existing Docker worker, serially. Fixture code is fixed and authored; the trusted local fixture backend never executes generated code. This evaluates a cached completion policy after an authored repair, not an interactive model repairing new repositories.

Freeze case definitions, exact template text/hashes, policy programs, selection receipt, contract, analysis, runner, dependencies, image and resource bounds before executing any of the nine cases. Record the external freeze hash in Git before opening outcomes. Snapshot source files make the freeze inspectable even after subsequent development. The implementer sees template definitions and authored both splits: separation is procedural, not human blinding. The same provenance interface and failure mechanism are intentionally shared, so this is limited template transfer, not independent real-repository validation.

## Execution and stopping

The runner first writes a durable reservation for every logical trial it starts. A completed result must replay against its frozen trace tip and match the candidate, case and plan before normalization. Resume reuses finalized results; a reservation without a finalized result stops rather than silently repeats. Retain timeouts, invalid outputs, refusals and infrastructure outcomes. No stochastic retries or candidate replacements. Any infrastructure-inconclusive slot prevents the primary comparison. An unexpected reference or fixture failure is retained and stops interpretation; fixing it would require a versioned amendment and an exploratory label for previously opened cases.

The allowance is exactly the 36 fixed local trials, at most four actions each, with the existing worker limits (30-second startup and 10-second execution per action). There are zero new inference calls and zero incremental API calls. Report local worker count/time separately from subscription cost, which remains unknown. This is a planning upper bound, not a promise of fixed wall time.

## Analysis and claims

Use the already implemented analysis contract: complete common grid, equal case weights within the **one source pool**, verified completion separate from functional correctness/freshness/refusal, and paired differences between frozen selectors. The three audit templates do not create three independent generation pools. With one pool, report descriptive counts only: no confidence intervals, significance claim, population failure rate, or equivalence claim. An identical selected ID implies identical selector audit outcomes; rerunning that policy three times would add no selection information, so evaluate it once and share the recorded outcome across methods.

Report all candidates plus the authored reference, the parent-to-selected change, and mechanism-sensitive versus unchanged cases. Report equal outcomes and ceiling effects directly. Successful generated repairs support feasibility of isolated execution and this narrow transfer only. They cannot establish a selector advantage, a naturally occurring model failure, or native Shinka evolution performance. The original broader hypothesis remains untested if this pool cannot discriminate methods. The audit is opened once; later tuning cannot recycle it as held out.
